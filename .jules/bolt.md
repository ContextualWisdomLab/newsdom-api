## 2024-05-18 - Defer Expensive Computations in Block Iteration
**Learning:** In `newsdom-api`'s parsing loop (`_build_page_dom` in `src/newsdom_api/dom_builder.py`), the codebase was allocating bounding box (`BoundingBox`) objects and performing expensive float conversions for *every* parsed block at the start of the block iteration. This is a performance anti-pattern because many block types (e.g., standard text blocks, headers, footers, page numbers, ads) do not actually use or preserve the bounding box. Eager allocation and conversion adds measurable overhead, especially when parsing large scanned PDFs with thousands of minor text blocks that will simply discard the generated bbox.
**Action:** Always defer expensive type conversions and object allocations (like `_bbox_from_values`) into the specific conditional branches that actually consume them. In parsing loops that process heterogeneous blocks, avoid eager instantiation of models until the block type has been identified and the model is definitively required.
